# Astro Stacker ユーザーガイド

このガイドは、現在のAstro Stackerで通常の天体スタックからHDR、新星景、移動天体、
タイムラプス素材までを処理するための操作説明です。すべての処理は元画像を変更せず、
プロジェクト、キャッシュ、中間素材、出力画像として保存されます。

## 1. 起動

プロジェクトのルートで次を実行します。

```bash
uv sync --locked
uv run astro-stacker
```

RAW現像、星検出、通常スタックにはPython依存関係だけで足ります。Plate Solveには別途、
ローカルのAstrometry.net本体と撮影画角に対応するindexファイルが必要です。

## 2. メイン画面とボタン

ツールバーには次の操作があります。

- 「プロジェクトを開く」: `.astrostacker` を読み込みます。`Ctrl+O`でも実行できます。
- 「プロジェクト保存」: 画像一覧、使用状態、処理設定、解析結果、表示状態を保存します。
- 「フレーム追加」: 現在表示しているフレーム種別へ画像を追加します。
- 「位置合わせ」: 恒星基準の位置合わせだけを実行します。
- 「スタック」: キャリブレーション、必要な位置合わせ、正規化、選別、スタックを実行します。
- 「保存」: 現在のスタック結果をFITS/TIFF/PNG/JPEGで保存します。
- 「Plate Solve」: フレーム一覧で選択中の画像をAstrometry.netで解析します。
- 「リセット」: 現在のプロジェクトを閉じて初期状態へ戻します。
- 「追加処理」: 位置合わせ画像出力、星マスク、HDR、新星景、地上マスク、
  タイムラプス、Bad Pixel Mapを選ぶドロップダウンです。

メニューにも同じ操作があります。ファイルやフォルダを一度選ぶと、その場所が保存され、
次のファイル選択画面は最後に使用したフォルダから始まります。

画面左はプロジェクトツリー、中央は画像プレビュー、下部はフレーム一覧とログです。
フレーム一覧では、チェックを外した画像を削除せず処理対象外にできます。

## 3. フレームの追加とプロジェクト

フレーム一覧で対象タブを選び、「フレーム追加」を押します。分類は次の通りです。

- Light: 星や天体が写った本画像
- Dark: Lightと同じ露出時間・温度で撮影した遮光画像
- Flat: 光学系の周辺減光やゴミを補正する均一光画像
- Flat Dark: Flatと同条件の遮光画像
- Bias: 最短露出の読み出しオフセット画像

フレーム一覧へのドラッグ＆ドロップも利用できます。プロジェクトを保存すると、元画像の場所、
フレームの有効状態、参照画像、処理設定、Plate Solve、位置合わせ履歴が復元可能になります。
解析履歴はプロジェクトに隣接するサイドカーファイルにも保持されます。

## 4. 通常の位置合わせとスタック

### 位置合わせだけ実行する

「位置合わせ」を押し、キャリブレーションのタイミング、使用する補正フレーム、参照画像、
星検出感度、最大星数を設定します。既存の位置合わせセッションが有効な場合は、後から追加した
未処理画像だけを同じ座標へ追加できます。

位置合わせで画像外となる領域は自動クロップせず、元画像と同じ出力寸法を維持します。
内部では有効領域をfloat32 Weight Maskとして扱います。

### スタックする

「スタック」で次を選びます。

- 使用画像: 位置合わせ後、または位置合わせ前
- 基準: 恒星、または彗星・小惑星などの移動天体
- 方法: Average、Median、Add、Sigma Clipping、比較明、比較暗、最大・最小除外平均
- 無効領域: 位置合わせ後の画像外領域をWeight Maskで除外
- 品質重み: FWHM、背景ノイズ、星数、楕円率、Alignment RMSなどから画像ごとの寄与を調整
- 露出正規化: 線形画像を露出秒で割って単位時間当たりの値へ変換
- 背景正規化: MedianまたはRobust推定で画像間の背景差を補正
- フレーム選別: 全画像、上位%、上位n枚、Score閾値、手動

JPEGなど現像済みの非線形画像では露出正規化の物理的意味が弱くなるため、RAW/FITS/TIFFの
線形データを推奨します。完全除外と低い品質重みは別の状態です。

## 5. 位置合わせ済み画像の書き出し

先に位置合わせを完了し、「追加処理 → 位置合わせ済み画像を書き出す」を選びます。
保存ダイアログで既存の出力形式とビット深度を指定すると、各Lightフレームが同じ参照座標の
画像として連番出力されます。ここではスタックせず素材だけを作成できます。

## 6. 星マスクと地上マスク

### 星マスク

星検出済みフレームを一覧で選び、「追加処理 → 星マスクを作成」を実行します。検出星の位置、
FWHM、明るさなどから、白を星、黒を非星領域とするマスクを保存します。設定値はプロジェクトの
星マスク設定を利用し、星サイズ、明るい星の拡張、Featherなどを処理基盤へ渡します。

### 地上領域の自動推定と編集

対象フレームを選び、「追加処理 → 地上領域を自動推定」を実行します。推定後は編集画面で
結果を確認し、Polygonの追加・削除、頂点移動、Feather調整、推定のやり直しができます。
信頼度が低い場合は警告を確認し、自動結果をそのまま確定せず修正してください。

## 7. HDR

HDRでは異なる露出の画像も含め、最初に全画像を一つの参照画像へ位置合わせします。
グループごとの独立位置合わせは素材間のずれにつながるため、通常は使いません。

1. Lightをすべて追加して位置合わせを実行します。
2. 「追加処理 → HDR」を選びます。
3. EXIFの露出時間・ISO・F値による自動グループ、またはフレーム順の手動グループIDを選びます。
4. 実行範囲を選びます。
   - 露出別Stackを保存して終了
   - 線形HDR Mergeまで
   - Tone Mappingまで
5. Tone MappingはGlobal、Local、Logから選び、必要ならLocal scaleとDetail strengthを調整します。

HDR Mergeは露出別スタックを露出時間で輝度へ換算し、飽和付近では短時間露出、暗部では
長時間露出を優先します。露出別スタック、線形HDR、Tone Mapping結果は別々の中間生成物です。

## 8. 新星景

「追加処理 → 新星景」では星空と地上を別々に処理し、必要な素材だけ、または最終合成までを
出力できます。

1. 星空用Lightを追加します。星空を恒星基準にする場合は先に全画像を位置合わせします。
2. 作成内容から、星空だけ、地上だけ、マスクだけ、全素材、最終合成まで、のいずれかを選びます。
3. 地上画像を同じLightから作るか、別撮り画像を選びます。
4. 境界処理を選びます。
   - 地上を完全にマスク
   - 光害フレームを作り滑らかに合成
   - ユーザー作成マスク
5. 自動推定された地上マスクをPolygon編集し、Featherを確認します。
6. 時間グループを分割しない、自動反転候補、手動分割から選びます。

地平線付近の星を保護する場合は星マスクを有効にします。光害フレーム方式ではBlur scale、
Transition width、背景強度を調整できます。出力には設定に応じてsky stack A/B、merged sky、
ground stack、ground mask、star mask、light-pollution frame、final compositeが含まれます。

地上固定Alignmentは地上領域の特徴点を使い、星の動きとは分離して地上を揃えます。
自動移動解析は星と地上の移動量・方向を比較し、方向反転の候補を時間グループとして提示します。
候補は強制されず、手動分割へ変更できます。

## 9. タイムラプス用n枚スタック

「追加処理 → タイムラプス用スタック」でWindow sizeとStepを設定します。例えばWindow 10、
Step 10は1〜10、11〜20の非重複グループ、Step 5は1〜10、6〜15のSliding Windowです。
最後の端数グループは出力するか捨てるかを選べます。

Alignmentは「なし」または「全画像を共通星座標へ位置合わせ」を選択します。共通星座標の場合は
先に全画像の位置合わせが必要です。各出力にはグループ開始・中央・終了時刻がメタデータとして
記録され、`stack_000001`から連番保存されます。

## 10. 彗星・小惑星などの移動天体

1. 「スタック」で「アライメント後画像」「移動天体基準」を選び、移動天体設定を開きます。
2. 手入力なら2枚以上の赤経・赤緯アンカーを指定します。
3. カタログなら検索語を入力し、NASA/JPL SBDBから天体を選択します。空欄検索は実行されません。
4. 「軌道計算」で各露光中央時刻のHorizons位置を取得します。
5. 基準画像をPlate Solveし、固定したい時刻の参照フレームを選びます。
6. 設定を確定してスタックします。

検索と軌道計算にはインターネット接続が必要です。通信エラーはダイアログとログに表示され、
処理中に別の検索は開始できません。観測地点コードの既定値`500`は地心です。高精度な近地球天体や
近距離彗星では、撮影地点に合うMPC observatory codeを指定してください。

## 11. Bad Pixel Map

DarkまたはBiasフレームを選び、「追加処理 → Bad Pixel Mapを作成」を実行します。Hot Pixel、
Cold Pixel、異常列を検出し、既存の画像保存形式でマップを保存します。Bayerデータを補間する処理では、
異なるCFA色を混ぜず同じCFA位置の近傍を使う設計です。現行UIはMap生成までを提供します。

## 12. 保存形式とメタデータ

入力はrawpy対応RAW、FITS、TIFF、PNG、JPEGです。出力はFITS、TIFF、PNG、JPEGから選べます。
内部処理は原則float32で、FITS/TIFFで利用可能な場合は32-bit floatを選択できます。

撮影日時、露出時間、ISO、F値など利用可能な撮影条件を出力へ引き継ぎます。複数画像の結果には
総露出時間や撮影条件の内訳を記録します。メーカー固有MakerNoteの完全な複製は保証しません。

## 13. 大容量処理、並列度、キャンセル

「設定 → 並列処理」で自動設定、逐次処理、またはワーカー数を指定できます。自動設定はCPU数と
利用可能メモリを考慮します。画像キャッシュは容量制限付きで、スタックはデータ量に応じてRAMと
一時memmapを切り替えます。大量画像を常時すべてRAMへ展開する設計ではありません。

処理中は画面下部の進捗とログを確認できます。「キャンセル」は各パイプラインへ停止要求を送り、
安全な処理境界で終了します。詳しい既定値は[処理速度とリソース設定](PERFORMANCE.md)を参照してください。

## 14. 困ったとき

- ボタンが無効: 必要なLight、選択フレーム、位置合わせ、またはスタック結果が揃っているか確認します。
- 星が検出されない: 星検出sigmaを下げ、ピント、露出、雲、強い背景勾配を確認します。
- Alignmentが失敗: 共通して写る星が十分ある画像を手動参照にし、最大星数を増やします。
- Plate Solveが失敗: `solve-field`の場所、indexファイル、画角、探索ヒントを確認します。
- JPL検索・軌道計算が失敗: 検索語、ネット接続、天体選択、観測地点コードを確認します。
- メモリ不足: 並列度を下げるか逐次処理にし、memmap用ディスク空きを確保します。
- 詳細な例外: 下部の「ログ」タブとエラーダイアログの詳細を確認します。
