# 処理速度とリソース設定

RAM 8GB・SSD 128GBのPCを想定した既定値です。Surface Go 3実機での測定はまだ行っていません。

## メモリとSSD

| 用途 | 既定の上限・方針 |
| --- | --- |
| 展開済み画像のRAMキャッシュ | 256MiB、最大10枚。両方を満たすようLRUで破棄 |
| Median / Sigma Clippingの作業バッファ | 256MiBと、その時点の利用可能RAMの1/4の小さい方 |
| スタック一時ファイル | 1回につき最大8GiB。作成後もSSDの空きを8GiB以上残す |
| 星検出の並列数 | CPU数、画像サイズ、空きRAM、ユーザー上限から自動調整 |
| 永続的な展開画像キャッシュ | 作成しない |

256MiBは**アプリ全体のメモリ上限ではありません**。読み込み中の画像、出力、キャリブレーションマスター、GUI、ネイティブライブラリは別途メモリを使用します。24MP画像1枚のfloat32配列はモノクロで約92MiB、RGBで約275MiBです。キャッシュ枠を超える画像は読み込めますが保持しません。星カタログとWCSは各フレームに保持し、画像の再デコードや計算を減らします。

Median / Sigma Clippingは全フレーム分が作業予算の半分以下ならRAM内で処理します。それ以上はOSの一時フォルダにmemmapを作成し、行単位で計算します。チャンクは中間配列・マスクのために入力サイズの8倍を見込んで分割します（最低1行）。最初の画像も一度だけ読み込みます。正常終了・キャンセル・例外ではマッピングを閉じ、一時ファイルを削除します。

必要な一時容量が上限を超える場合は、書き込み前に必要容量を表示して停止します。画像枚数を減らすか、ディスク一時ファイルを使わないAverage / Add / 比較明 / 比較暗 / 最大・最小除外平均を選べます。入力画像・出力画像・Astrometry.netのindexはこの上限に含みません。indexは撮影画角に必要なものを管理してください。

開発者向けの既定値は `src/astro_stacker/core/resources.py` に集約しています。`ImageManager(max_cache_bytes=...)` と `ImageCombiner(memory_limit=..., disk_limit=..., disk_reserve=..., temp_dir=...)` で上書きできます。

## 高速化の内容

- 画像追加のメタデータ読み込みは2スレッド。フレーム一覧の更新は1バッチにつき1回。
- EXIFのMakerNote・サムネイル等の詳細解析を省略し、読み込み時の全画像コピーと重複clipを削減。
- 画像キャッシュはファイルパス・サイズ・更新時刻・変更時刻で識別。変更されたファイルは再読み込み。同時に同じ画像を要求した場合も1回のロードを共有。
- 星検出の背景推定は最大512×512画素の格子標本。Bayerの片側の色だけを拾わない奇数間隔を使用。星の位置検出そのものは元解像度で実施。
- FWHMの品質評価は明るい最大50星。位置合わせは明るい順の星を使う。未補正画像の星検出は、入力と検出設定が同じなら再利用。補正・変形済みの入力は再計算。
- アフィン変形はOpenCVの線形補間へ変更。補間座標の量子化により旧skimage版と画素値が完全一致するわけではありません。Bayer各色の原点も考慮して変形し、恒等変換はコピーを省略。
- 平均・加算等は1枚ずつ処理し、配列をその場で更新。キャッシュ内の入力配列は変更しない。
- Average / Addの通常有限データはWeight配列の生成を省く高速経路を使用。NaNを検出した時だけ画素別Weightへ切り替える。
- スタック前の読込、Calibration、Bad Pixel補正、Debayer、Alignment変換をメモリ制限付きで先読みし、集計と重ねる。結果の加算順は入力順を維持する。
- 星検出の旧2ワーカー固定上限を廃止し、「設定 → 並列処理」の上限と空きRAMから決定する。
- 全LightにFITS WCSがある場合は、ユーザー選択により星検出・照合を省略してWCSからHomographyを求める。
- Plate Solveは星抽出時の長辺を約2048画素以下に自動縮小。`solve-field`側で縮小するため、返されるWCSは元画像の座標。不要な出力ファイルを抑制。同一ファイル・設定での成功結果はアプリ内で再利用。

Plate Solveの自動縮小は「赤経・赤緯 / カタログ / Plate Solve 設定...」でオフにできます。星が少なく失敗する画像はオフにし、Downsampleを1または2にしてください。この設定はツールバーからのPlate Solveにも適用します。探索中心やピクセルスケール範囲が分かる場合の制限も引き続き使用できます。Astrometry.netの入出力仕様は[公式README](https://astrometry.net/doc/readme.html)を参照してください。

## DeepSkyStackerとの速度差

DeepSkyStacker（DSS）の公式ソースとガイドを確認すると、ネイティブC++、複数プロセッサ、
SIMD/AVX、登録情報の再利用に加え、FITS WCSからオフセットと回転を求める経路は星位置比較より
非常に高速であると説明されています。

- [DSS公式ソース](https://github.com/deepskystacker/DSS)
- [DSS公式ユーザーガイド](https://github.com/deepskystacker/DSS/blob/master/Help/english/userguide.htm)

Astro StackerはPythonでUIとPipelineを構成しますが、画素処理はNumPy/OpenCVのネイティブコードへ
まとめ、上記のWCS高速経路、並列度、キャッシュ、先読みを取り入れています。ただし、RAWデコーダ、
画像サイズ、星数、ストレージ、選択した補正やSigma Clippingで時間は変わるため、DSSの
「1枚1秒未満」を全環境で保証するものではありません。速度比較は同じ入力、同じDebayer・Calibration、
同じスタック方法、中間ファイル出力の有無を揃えて行ってください。

2026-09-10の合成1536×1024・1ch・12枚の確認では、WeightなしAverageの中央値は高速経路導入前
約0.029秒から約0.004秒になりました。これは配列が既にRAMにある集計部分だけの値で、RAW読込と
星検出を含む実撮影セット全体の時間ではありません。

## HDRの性能・正規化上の注意

HDRの自動グループ化は露出時間、ISO、F値を使いますが、線形Radiance換算は現在露出時間を基準に
しています。ISOゲインやF値の入射光量差をカメラ固有特性まで含めて補正していないため、現状は
ISOとF値を固定し、露出時間だけを変えたブラケットを推奨します。

## スタック方法

| 方法 | 内容 | ディスク一時領域 |
| --- | --- | --- |
| Average | 単純平均 | 不要 |
| Median | 中央値 | データ量に応じる |
| Add | 加算 | 不要 |
| Sigma Clipping | 平均・標準偏差を使って外れ値を反復除外後、平均 | データ量に応じる |
| 比較明 (Maximum) | 画素・チャンネルごとの最大値 | 不要 |
| 比較暗 (Minimum) | 画素・チャンネルごとの最小値 | 不要 |
| 最大・最小除外平均 | 最大と最小を1個ずつ除いて平均。3枚以上必要 | 不要 |

比較明・比較暗はノイズ低減を目的とする平均の代わりとは限りません。最大・最小除外平均は同値が複数あっても各1個だけ除外し、3枚なら中央値になります。

## 検証と速度計測

外部画像不要の回帰テスト:

```bash
uv run pytest
```

数値結果、入力配列の保持、RAM/ディスク両経路、キャンセル・例外時の削除、空き容量判定、画像キャッシュの更新・同時ロード、星の座標、WCSの再利用を検証します。従来のローカル画像依存の実験スクリプトは自動収集の対象外です。

再現可能な合成画像ベンチマーク:

```bash
uv run python scripts/benchmark_processing.py
# 手元RAWの読み込みも計測する場合
uv run python scripts/benchmark_processing.py --raw path/to/image.ARW
```

2026-09-09、手元のApple Silicon Mac / Python 3.12で測定。1536×1024・1ch、12枚、各処理をウォームアップ後3回測定した中央値。ロード計測には手元のARWを使用。OSのファイルキャッシュが効いた状態で、実撮影セット全体・Surface Go 3の速度を保証するものではありません。

| 処理 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 星検出＋品質評価 | 0.289秒 | 0.119秒 |
| 画像変形 | 0.00972秒 | 0.000454秒 |
| Average 12枚 | 0.00345秒 | 0.00195秒 |
| Median 12枚 | 0.153秒 | 0.0716秒 |
| Sigma Clipping 12枚 | 0.168秒 | 0.0981秒 |
| RAWメタデータ | 0.0368秒 | 0.0185秒 |
| RAW画素読み込み | 0.0372秒 | 0.0323秒 |

追加で実RAW2枚の星検出・位置合わせを確認。変更前6.02秒、変更後2.84秒（各1回）。検出星数は両方140/130個、マッチ数36→39、残差RMS 0.355→0.272画素でした。明るい星を優先する変更により、使われる星と変換行列は変わります。

実RAW1枚のPlate SolveもローカルAstrometry.netで成功。変更前6.72秒、変更後4.40秒（各1回）。再実行時はキャッシュにより約0.00014秒でした。ピクセルスケールは6.2426→6.2419 arcsec/pix。初回速度はindex・探索範囲・星の数・OSキャッシュに大きく依存します。
